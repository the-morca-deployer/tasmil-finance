# Admin CSV Export + Strategy Marketplace Tracking Page — Design

**Date:** 2026-07-02
**Repos touched:** `backend` (NestJS), `tasmil-finance` (Next.js admin)
**Out of scope:** changes to the `tasmil-strategy` app (its standalone admin page stays as-is but stops being extended)

## Goals

1. Every data table in the tasmil-finance admin gets a CSV export button that downloads the **full dataset** (not just the visible page), generated by the backend.
2. A new admin page tracks the tasmil-strategy marketplace: all strategies with statuses and approval actions, deposits/TVL, and users/activity.

---

## Part 1 — CSV export for all admin tables

### Backend

**Shared CSV service.** `CsvExportService` in `backend/src/common/csv/` with one method:
`toCsvResponse(res, filename, columns, rows)` — takes column definitions (`{ key, header }[]`) and rows, writes a `text/csv; charset=utf-8` body with header row, RFC-4180 escaping (quote fields containing `,`, `"`, or newlines; double embedded quotes), and sets `Content-Disposition: attachment; filename="<name>-YYYY-MM-DD.csv"`. Dates serialize as ISO-8601 strings; nulls as empty cells.

**Export endpoints.** One `GET .../export` per table, guarded by the existing `AdminGuard`, fetching the full dataset via the module's existing service (Prisma query without pagination). Filters supported by the list endpoint are also accepted by the export endpoint.

| Admin page | Endpoint | Notes |
|---|---|---|
| Waitlist | `GET /api/admin/waitlist/entries/export` | accepts same `status`/search filters as list |
| Topups | `GET /api/admin/topups/export` | accepts `rail`, `status` |
| Quests (quest wallets) | `GET /api/admin/quest-wallets/export` | replaces the page's ad-hoc client-side export |
| Codes | `GET /api/admin/codes/export` | |
| Campaigns | `GET /api/admin/campaigns/export` | |
| Quest campaigns | `GET /api/admin/quest-campaigns/export` | |
| Tier bands | `GET /api/admin/tier-bands/export` | small config table; still gets the button for consistency |
| Sponsor logs | `GET /api/admin/sponsor/logs/export` | |
| Dashboard / analytics stats | `GET /api/admin/stats/registrations/export` | daily registration + quest stat rows |

Export columns mirror the corresponding list endpoint's fields, plus record IDs and created/updated timestamps.

These tables are admin-scale (hundreds to low tens of thousands of rows); a buffered (non-streaming) response is acceptable. If a table ever outgrows this, switch that one endpoint to a streamed cursor without changing the contract.

### Frontend (tasmil-finance)

- **`ExportCsvButton`** in `src/features/admin/components/export-csv-button.tsx`: props `{ endpoint: string, params?: Record<string, string> }`. Shows a download icon + "Export CSV", spinner while in flight, error toast on failure.
- **`adminDownload(path)`** helper added to `src/features/admin/lib/admin-fetch.ts`: fetches with the admin Bearer token, reads the response as a blob, extracts the filename from `Content-Disposition` (fallback: derived from path + date), and triggers a browser download. 401 clears auth and redirects to `/admin/login`, same as `adminFetch`.
- Each admin page places the button next to its table header, passing its current filter values so the export matches what the admin is looking at.
- The quests page's local `exportCsv` helper is deleted in favor of the shared button.

### Proxy routes

**Amended during planning:** no proxy routes are needed. `next.config` already rewrites `/api/admin/:path*` (and after a one-line addition, `/api/marketplace/:path*`) straight to the backend, and App Router route handlers only shadow their exact paths — so new `.../export` endpoints are reachable from the browser at the same path, CSV body and headers intact.

## Part 2 — Strategy marketplace tracking page

### Placement

- New sidebar entry **"Strategies"** in the tasmil-finance admin.
- Route: `src/app/admin/(app)/strategies/page.tsx`.
- Feature module: `src/features/admin-strategies/` (components, hooks, types) — no imports from other features, per the isolation rule.
- Three tabs on one page.

### Strategy status model (backend change)

`Strategy` currently has no status column — and no rejected state. Add a migration (in `backend/prisma/migrations/`, per the shared-DB rule):

- New column: `rejected_at TIMESTAMP NULL` (`rejectedAt` in the Prisma model).

Derived status, computed in the marketplace service and returned as a `status` string:

| Status | Condition (evaluated in this order) |
|---|---|
| `REJECTED` | `rejectedAt != null` |
| `PENDING` | `isApproved == false` |
| `PAUSED` | `pausedAt != null` |
| `PUBLISHED` | `isApproved == true && isActive == true` |
| `INACTIVE` | `isApproved == true && isActive == false` |

### New backend endpoints

**Amended during planning:** the marketplace module's existing admin endpoints use a *different* auth system (`AuthGuard`+`AdminGuard`, user JWTs from `/auth/login` — what the tasmil-strategy app uses) than the tasmil-finance admin (`AdminAuthGuard`, admin JWTs from `/admin-auth`). The tasmil-finance admin token cannot call them. So the new endpoints live in a new `MarketplaceAdminController` in the **admin module** at `admin/marketplace/*`, guarded by `AdminAuthGuard`:

| Endpoint | Returns |
|---|---|
| `GET /api/admin/marketplace/strategies?status=` | All strategies: id, name, slug, derived status, publisher name/address, base asset, risk tier, perf fee bps, keeper wallet, publish tx hash, TVL, depositor count, publishedAt. TVL and depositor count come from `StrategyPerformance` (tvlUsd, userCount). |
| `GET /api/admin/marketplace/overview` | KPI aggregates: total TVL, total depositors, counts by status, publisher count. |
| `GET /api/admin/marketplace/publishers` | Publishers from `StrategyPublisher`: name, stellar address, commission bps, strategy count, created date. |
| `POST /api/admin/marketplace/strategies/:id/approve` | Sets `isApproved/isActive = true` and clears `rejectedAt`. |
| `POST /api/admin/marketplace/strategies/:id/reject` | Sets `rejectedAt = now()`. Only valid while the strategy is `PENDING`; returns 409 otherwise. |
| `GET /api/admin/marketplace/strategies/export` | CSV of the strategies table (Part 1 utility). |
| `GET /api/admin/marketplace/publishers/export` | CSV of the publishers table. |

Reused as-is (public, no auth): `GET /marketplace/strategies/:id/participants`, `GET /marketplace/leaderboard`. The marketplace module's own `admin/pending` + `approve` endpoints stay untouched for the tasmil-strategy app; `listPendingStrategies` additionally excludes rejected rows.

### Tabs

**Tab 1 — Strategies.** Table of all strategies with the columns above and a status filter (All / Pending / Published / Paused / Rejected / Inactive). Pending rows show **Approve** and **Reject** buttons; both actions require a confirm dialog and invalidate the list on success. Export CSV button included.

**Tab 2 — Deposits & TVL.** KPI cards from the overview endpoint (total TVL, total depositors, published count). Per-strategy breakdown table (name, TVL, depositor count, base asset). Clicking a row opens a participants panel backed by `GET /marketplace/strategies/:id/participants`. Export CSV button on the breakdown table.

**Tab 3 — Users & Activity.** Publishers table (from the new publishers endpoint) and the marketplace leaderboard (reusing `GET /marketplace/leaderboard`). Export CSV button on the publishers table. **Faucet claims are out of scope** — the backend stores no faucet data.

### Data flow

Same as the rest of the admin: React Query hooks in `features/admin-strategies/hooks/` → `adminFetch` → Next.js proxy routes under `src/app/api/admin/strategies/*` → backend with the admin JWT.

### Error handling

- Approve/Reject failures surface the backend message in a toast; the row stays in place.
- 401 anywhere follows the existing clear-auth + redirect-to-login behavior.
- Empty states per tab ("No strategies yet", etc.) matching existing admin pages.

## Testing

- **Backend:** unit tests for `CsvExportService` (escaping, headers, filename), each export endpoint (guard + shape), derived-status logic, and the reject flow (pending-only, 409 otherwise).
- **Frontend:** Jest tests for `ExportCsvButton` (loading/error states, download trigger) and the strategies table (status filter, approve/reject actions), following the existing `features/admin/__tests__` pattern.

## Deployment order

1. `backend` first (new endpoints + migration) — additive, safe to deploy alone.
2. `tasmil-finance` second (buttons, new page, proxy routes).
Both via feature branch → PR → `deploy/prod`, with CI checked after each merge.
